
**N = 358.** The count includes 353 downloaded files and 5 committed samples, and 4 of those samples
are copies of downloaded files, so there are 354 distinct files. Totals such as cell counts include the
duplicates.

Every rejection is listed with its reason in `eval/results/2026-11-05-m0-corpus-load.json`:

| Rejected | Files | Assessment |
|---|---|---|
| Corrupt zip packages | 14 | Mostly fuzzer files, plus `deep-data.xlsx`, which has no zip end record |

| XML entity bombs | 4 | Correct: DTDs are disabled, so the entity attack fails |

| Pre-release Excel 2007 format | 1 | Different namespace and elements, so not supported |
| Invalid content | 3 | `r="B"`, `r="A0"`, and a row number beyond the integer range |

**Limit of this check:** POI's test data is not representative of real models.

## Beyond the exit check: are the values right?

"No crash" says nothing about correct decoding, so `PoiCrossCheck` compares stored values and formula
text with Apache POI, in both directions. POI's evaluator is never called (ADR-0011).

```
$ ./gradlew -q :cellerity-eval:crossCheck -PcrossCheckArgs="corpus/downloads"
[exit 0]

$ bash corpus/download.sh --verify-only
corpus: 353 verified (353 already present), 0 failed

```

Explained differences, each checked against raw XML:

- **233 array-member cells.** Only the master of an array range stores `<f>`. POI presents the members
  as formula cells. Their cached values are still compared and agree.
- **25 empty stored numbers.** `<c t="n"><v></v></c>` stores nothing. POI reports 0, and we report
  blank.

Not cross-checked: formula text of shared-formula cells (POI expands them, and expansion is M1), and
the 7 files above.

## What went wrong on the way

1. **A false pass.** `new XSSFWorkbook(File)` opens read-write and saves on close, so the first
   cross-check rewrote 320 corpus files and dropped `sharedStrings.xml`. A later run reported zero
   disagreements while comparing only 236 files. The checksums exposed it. POI is now read-only, the
   corpus is re-verified afterwards, and the check fails below 300 compared files.
2. **Over-strict rejection.** `60825.xlsx` was rejected because of one sheet entry with `r:id=""`. It now
   loads, with that sheet listed as empty.
3. **Formatter version.** google-java-format 1.37 breaks Spotless's glue code, so the build uses the
   version Spotless pins.
