**State: exit checks pass, and CI is green (`build` run 42246679913, `eval` run 42246679979, on `7c3ec48`).**

Corpus output is copied from CI, on Ubuntu with Temurin 25, on 2026-11-06. Design: `docs/design/graph.md`.

## Exit check 1: changing one input recomputes only affected cells

This is asserted by counting evaluations, in `IncrementalWorkbookTest.changingAnInputRecalculatesOnlyWhatItAffects`:
a workbook with two chains of three formulas and 100 unrelated formulas evaluates exactly 3 after one change.

```
$ ./gradlew :cellerity-interp:test --tests '*IncrementalWorkbookTest'
```

On the corpus (`make recalc`, which fails on any disagreement, or if a recalculation exceeds what the graph predicted):

```
recalc: 781 files, 3 left out for static cycles, 0 timed out, 0 crashed
1099 changes, 2533277 formula cells compared, 0 disagreements
evaluated 88717 formulas, where full recalculations evaluated 1421806 (6.24%), 0 over budget
```

Each change was compared on every formula cell with a new `WorkbookEvaluator` given the same inputs. A jqwik property
does the same on random workbooks. Results are in `eval/results/2026-11-06-m3-recalc.json`.

## Exit check 2: cycles are detected and reported

Tarjan's algorithm finds static cycles, and `cellerity verify` names them. `CycleReportTest` proves this on a real
`.xlsx` file, which prints:

```
possible cycles: 1
  Loop!A1 -> Loop!B1
feature cycle: 2
```

Cells in a cycle keep their cached value, and count as an unsupported feature rather than a mismatch.

## Volatile and dynamic functions

These recalculate on every change, along with what reads them. Excel treats `OFFSET` and `INDIRECT` the same way.

- `NOW`, `TODAY`, `RAND`, `RANDBETWEEN`, `CELL`, `INFO`
- `OFFSET`, `INDIRECT`
- A range operator such as `A1:INDEX(...)`
- `SUMIF` and `AVERAGEIF` whose third argument differs in size from their first, as they read beyond it

## What these numbers do and do not mean

- **6.24% is not a speed claim, and depends on the workbook.** It is a count of evaluations for these changes. Times come in M4.
- **The changes are a sample.** At most 3 per file, chosen from numeric inputs that some formula reads directly. A file with
  few such inputs contributes fewer, for 1,099 in total. Editing a heavily used input costs far more than the average.
- **Agreement does not prove the graph is complete.** It shows no missed dependency on these changes. The corpus did not
  catch the relative-name bug below, for instance.
- **Full recalculations evaluate only what we can calculate.** Formulas with external links keep their cached values in both,
  so about half of Enron's formulas are outside this comparison, as in M2.
- **3 files with static cycles are left out** of the differential, since a cycle's values can depend on where evaluation
  starts. Their cells are not compared.
- **Precision is deliberately imperfect.** Both branches of an `IF` count as precedents, so a change to an untaken branch
  recalculates the cell without changing it. `verify` calls cycles "possible" for the same reason.

## What this milestone found

- **Only one cell in a cycle was marked.** The others were calculated from a cached value and could count as real
  mismatches. The new CLI test found this, and POI's compared count fell by one (96.4392% of 23,955).
- **Relative defined names were unsound in the graph.** The interpreter shifts a name's references by the formula's position,
  and the graph did not, so a change could have missed a dependent and left a stale value. This came from reading the code,
  not from a test: 0 disagreements on the corpus came both before and after the fix. It now has tests.
- **The first saving figure was overstated.** It reported 3.51% against all formulas, including ones a full recalculation
  never evaluates. The measured figure is 6.24%.

## Known limits

- Running totals such as `SUM($A$1:A5000)` down a column make each lookup linear in the number of areas read.
- Setting a cell that holds a formula keeps its old precedents, so it can recalculate too much.
- A cycle made at run time through `INDIRECT` or `OFFSET` is invisible to the graph. The evaluator catches it.
